## 1. The preflight breaker is not reset by a compliant commit

### What was measured

`plugin-claude-code/scripts/pre-commit-preflight-check.sh` writes the breaker
`aria-preflight-denies-<sid>[.agent-<id>]` at line 196 and never removes it
(`grep -rn aria-preflight-denies` → 4 hits, one per port, all writes). The script's own comment
promises "three consecutive denials with no compliant commit between them".

⚠ **The handoff's premise needs one correction.** There is no separate "skip" record. A compliant
commit is one where the session marker `aria-preflight-<sid>` is non-empty, and the `/preflight`
skill writes that marker for a skip as much as for a run. Line 125 (`[ -s "$MARKER" ] && exit 0`)
exits **before** the breaker, so after a skip the stale count is never consulted. The handoff's
proposed test ("2 denials → skip → 2 more still deny") therefore cannot fail on current code: the
2 later commits are never denied at all, with or without a fix.

Driven through the real hook (`preflight_gate: deny`, scratch repo, predictions declared first):

| step | verdict | breaker |
|---|---|---|
| commit 1, commit 2 (no marker) | DENY, DENY | 1, 2 |
| marker written (a skip), commit 3, commit 4 | allowed at line 125 | **2, 2** |
| marker removed, commit 5, commit 6 | DENY, **DEGRADED** | 3, 4 |

**So the defect is reachable only when the marker disappears mid-session.** Concrete ways: macOS
clears old files in `$TMPDIR`, and sessions here run for days; or a user deletes the marker to
re-arm the gate. Then the gate degrades after one denial instead of three. Narrow, but the code
does not do what its contract says, and the fix is one line.

### Fix

On the marker-allow path, remove this agent's breaker file before exiting. That needs the breaker
key computed before line 125, so the `lib-state-key.sh` source and the `BREAKER=` assignment move
up, unchanged.

The reset is per agent, the same key the denials use: a subagent's compliant commit clears that
subagent's count, not its parent's (v2.54.1 contract, test block [10b]).

### Options considered

| option | verdict |
|---|---|
| **A. Reset at the marker-allow exit** | **chosen** — matches the stated contract exactly |
| B. Reset on every allow path (no code staged, docs-only, warn-mode allow) | rejected: those commits are not compliant. Resetting on them changes the contract from "consecutive denials" to "denials since the last commit of any kind", which nobody asked for |
| C. Have the `/preflight` skill delete the breaker when it writes the marker | rejected: the skill is prose the model follows, not enforced code, and it does not know the per-agent suffix |
| D. Leave it and document the residual as inert | rejected: the code contradicts its own comment, the fix is one line, and the residual is reachable (marker loss) |

### Ports

| port | hook | how it changes |
|---|---|---|
| claude-code | `scripts/pre-commit-preflight-check.sh` | canonical edit |
| antigravity | `bin/pre-commit-preflight-check.sh` | regenerated by `build.sh:201` (byte-identical today apart from paths — `diff` after `scripts/`→`bin/` = identical) |
| codex | `bin/pre-commit-preflight-check.sh` | hand-splice. ⚠ **Codex has TWO compliant exits** (prospect finding): the session marker (line 119) and a per-repo `REPO_MARKER` (line 120, written by codex's own `/preflight` at `skills/preflight/SKILL.md:227`). Reset on **both**, or a repo-marker-allowed commit leaves the count stale. |
| cursor | `scripts/aria/pre-commit-preflight-check.sh` | hand-splice; its breaker has **no agent suffix** (line 119), keep that |

### Test

One parametrised block in `plugin-claude-code/tests/test-preflight-gate.sh`, run against **all four**
hook files. Measured during the prospect: all four accept the same input JSON and reproduce the same
bug signature (`DENY DENY | SILENT | DENY DEGRADED`), so codex and cursor, which ship the hook with
no test today, get a behavioural check, not a grep:

1. 2 denials (counts 1, 2).
2. Write the marker; 1 commit → allowed, **breaker file gone**.
3. Remove the marker; 3 commits → **all DENY**; 4th → DEGRADED.

Plus a codex-only arm: same sequence with codex's `REPO_MARKER` as the compliant exit instead of
the session marker.

**Red on current code:** in step 3 the 2nd commit degrades, on all four hooks (measured).
**Mutation:** delete the new `rm` line in one port → only that port's arm goes red. Seen red before
trusted. The existing blocks [10] and [10b] must stay green (positive controls for the breaker
itself).

## 2. The rules-digest test only checks rule numbers

### What was measured

`plugin-claude-code/tests/test-aria-rules-digest.sh:29` asserts that the set of rule numbers in
`rules/aria-rules.md` equals the set in `template/rules/working-rules.md`. Nothing ties a digest
line's TEXT to its source rule. Recorded 2026-08-26 (CLAUDE.md footer): reverting Rule 23's digest
text left the suite green. Re-confirmed by reading the test: no assertion reads text.

### Fix — a digest lock

A sidecar, `plugin-claude-code/tests/fixtures/aria-rules.digest-lock.json`, records for each rule N.
(Prospect finding: **not** under `rules/`. The SessionStart writer installs `aria-rules.md` by name
only (`session-start-check.sh:108`), so a lock there would never reach `~/.claude/rules`, but it
would ship in every plugin zip as dev-only data. `tests/` is excluded from every artifact.)

- `source`: sha256 of rule N's section in `working-rules.md` (from `### N.` up to the next `### `)
- `digest`: sha256 of rule N's line(s) in `aria-rules.md`

The test recomputes both and requires each to match the lock. Then:

- a source rule edited without reviewing its digest line → red, naming the rule
- a digest line reverted or edited alone → red, naming the rule
- both updated and the lock refreshed → green

Refreshing the lock is a separate, deliberate command, `plugin-claude-code/tests/relock-rules-digest.sh
<rule#> [<rule#>...]`, and it never runs inside the test. **It takes explicit rule numbers and has no
"all" mode** (prospect finding, pattern `precedent-ported-across-a-subsystem-boundary`). The
`check-port-drift.sh --update all` model this borrows from restamps everything blindly, which is the
exact bulk re-baseline an earlier session refused for codex because it would "assert a parity that
does not exist". Naming each rule makes each restamp a statement that that rule was reviewed.
`--init` writes a lock for every rule and refuses when a lock already exists.

### Options considered

| option | verdict |
|---|---|
| A. Digest title equals source title | rejected: titles are deliberate paraphrases — measured, rules 1–3 and 5–10 all differ (`Scope tasks tightly, but keep the whole system in view` vs `Scope tightly, keep the system in view`) |
| B. Each digest line shares a distinctive phrase with its source (the handoff's sketch) | rejected: a literal-phrase check over prose that several sessions edit checks the wording, not the fact. It goes red on a harmless rewording and green on a stale line that keeps one old phrase. There is no fixed set of spellings to enumerate |
| C. Generate the digest from the source | rejected: the digest is a hand-written summary plus standing directives that exist nowhere else; no generator can write it |
| D. Put the source hash in an HTML comment on each digest line | rejected: `aria-rules.md` is loaded into every session, so 38 hash comments are permanent context cost and noise the model reads |
| **E. Sidecar lock (both hashes per rule)** | **chosen** — the model never loads it; precedent in `PORT-LEDGER.json` |

### Scope

Canonical digest only. `plugin-antigravity/rules/aria-rules.md` is **regenerated** by
`build.sh:170-194` (canonical with paths substituted; its 38 rule lines are byte-identical to
canonical), and `tests/repros/port-generation-idempotence.sh` already guards that generation. It is
covered transitively, with no second lock. A digest named `aria-rules.md` exists in no other port.

### Test

1. The lock exists and parses; positive control: it holds one entry per source rule number.
2. Every rule's two hashes match.
3. **Force red before trusting it:** revert Rule 23's digest line to its 2026-08-26 text → the
   suite must name Rule 23. Restore from a byte backup, then `cmp`. Separately, change one word
   in one source rule section → must name that rule.
4. The existing number-set assertion stays (it catches an added or removed rule with a clearer
   message than a missing lock entry).
